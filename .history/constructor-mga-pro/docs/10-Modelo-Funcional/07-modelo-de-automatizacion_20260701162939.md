# 07 — Modelo de Automatización

## Propósito

Este documento define el modelo funcional de automatización del Constructor MGA Pro.

Su finalidad es establecer qué procesos pueden ejecutarse automáticamente, cuáles requieren validación del usuario y cuáles siempre permanecerán bajo decisión humana.

El objetivo no es automatizar por automatizar.

El objetivo es automatizar aquello que aumente la productividad sin sacrificar la calidad técnica del proyecto.

---

# Objetivo

Lograr un equilibrio entre inteligencia artificial, reglas de negocio y criterio profesional.

La automatización deberá reducir tiempos de formulación sin disminuir la confiabilidad de los resultados.

---

# Principios

- Automatizar tareas repetitivas.
- Mantener el control técnico del proyecto.
- Explicar toda acción automática.
- Permitir la intervención del usuario en cualquier momento.
- Registrar todas las acciones en el historial del proyecto.

---

# Niveles de automatización

## Nivel 1 — Asistencia

El sistema únicamente sugiere.

Ejemplos:

- Sectores.
- Tipologías.
- Productos MGA.
- Indicadores.
- Riesgos.

La decisión final corresponde al usuario.

---

## Nivel 2 — Automatización supervisada

El sistema completa componentes cuando existe suficiente evidencia.

Ejemplos:

- Diagnóstico preliminar.
- Problema central.
- Objetivos.
- Cadena de valor.
- Productos.
- Actividades.

Antes de consolidar la información, el usuario podrá revisarla.

---

## Nivel 3 — Automatización inteligente

El sistema ejecuta procesos internos sin intervención del usuario.

Ejemplos:

- Recalcular cobertura.
- Actualizar reportes.
- Ejecutar el Inspector.
- Actualizar el Semáforo.
- Recalcular calidad.
- Registrar historial.

Estas acciones no modifican el contenido técnico del proyecto.

---

# Procesos automatizables

El Constructor MGA Pro podrá automatizar:

- Clasificación del proyecto.
- Identificación del sector.
- Identificación del producto MGA.
- Organización de información.
- Actualización de estados.
- Generación de reportes.
- Consolidación de resultados.
- Verificaciones de coherencia.

---

# Procesos que requieren confirmación

Siempre deberán solicitar validación del usuario cuando impliquen:

- Cambiar el problema central.
- Cambiar objetivos.
- Sustituir indicadores definidos por el usuario.
- Modificar presupuesto.
- Eliminar información existente.
- Reemplazar documentos.

---

# Procesos nunca automatizables

El sistema nunca deberá decidir por sí solo:

- La aprobación final del proyecto.
- La radicación ante una entidad.
- La firma de documentos.
- La adopción de decisiones administrativas.
- La aceptación de riesgos institucionales.

---

# Integración

Este modelo será utilizado por:

- Maestro MGA.
- Motor de Decisiones.
- Motor de Flujo.
- Motor de Aprendizaje.
- Project Core.

---

# Resultado esperado

El Constructor MGA Pro deberá ejecutar automáticamente todas las tareas repetitivas y de apoyo técnico, permitiendo que el formulador concentre su esfuerzo en las decisiones estratégicas del proyecto.
