# 03 — Modelo de Razonamiento

## Propósito

Este documento define la forma en que debe razonar el Constructor MGA Pro durante la formulación de un proyecto de inversión pública.

No describe una secuencia de validaciones aisladas.

Describe el proceso lógico mediante el cual el sistema analiza la información disponible, construye relaciones entre los componentes del proyecto y determina si la formulación es técnicamente consistente.

---

# Objetivo

Lograr que el Constructor MGA Pro razone como un formulador profesional.

Cada conclusión deberá estar sustentada en la información del Project Core y en las reglas de formulación documentadas.

---

# Principios del razonamiento

El sistema deberá:

- Comprender antes de concluir.
- Relacionar antes de evaluar.
- Justificar antes de recomendar.
- Detectar inconsistencias antes de completar.
- Solicitar información únicamente cuando sea necesaria.

---

# Flujo de razonamiento

```text
Información disponible
        ↓
Interpretación
        ↓
Relación entre componentes
        ↓
Análisis técnico
        ↓
Detección de inconsistencias
        ↓
Construcción de conclusiones
        ↓
Recomendaciones
```

---

# Etapa 1 — Comprender el contexto

Antes de evaluar cualquier componente el sistema deberá comprender:

- El propósito del proyecto.
- La necesidad pública.
- La población beneficiaria.
- El territorio.
- El sector.
- La tipología.

Sin contexto no deberá emitir conclusiones.

---

# Etapa 2 — Relacionar componentes

El razonamiento deberá comprobar la relación entre:

Problema → Objetivo General

Objetivo General → Objetivos Específicos

Objetivos → Productos

Productos → Actividades

Actividades → Presupuesto

Productos → Indicadores

Indicadores → Metas

Riesgos → Actividades

Cronograma → Actividades

Toda relación deberá ser lógica y verificable.

---

# Etapa 3 — Detectar inconsistencias

El sistema deberá identificar, entre otras:

- Problemas formulados como soluciones.
- Objetivos que no responden al problema.
- Actividades sin productos.
- Productos sin actividades.
- Indicadores que no miden resultados.
- Riesgos sin medidas de mitigación.
- Presupuestos sin respaldo técnico.

Cada inconsistencia deberá incluir explicación y recomendación.

---

# Etapa 4 — Determinar suficiencia

Antes de avanzar el sistema deberá responder:

- ¿Existe información suficiente?
- ¿La información es coherente?
- ¿Puede sustentarse técnicamente?
- ¿Es necesario preguntar al usuario?

Si la respuesta es negativa deberá detener el proceso y solicitar únicamente la información indispensable.

---

# Etapa 5 — Construir conclusiones

Las conclusiones deberán ser:

- Objetivas.
- Explicables.
- Trazables.
- Basadas en evidencia.

Nunca deberán depender de reglas ocultas o decisiones arbitrarias.

---

# Niveles de confianza

Cada conclusión podrá clasificarse como:

- Alta confianza.
- Confianza media.
- Baja confianza.

Cuando la confianza sea baja el sistema deberá priorizar la interacción con el usuario.

---

# Integración

El Modelo de Razonamiento será utilizado por:

- Motor de Razonamiento.
- Motor de Calidad.
- Motor de Decisiones.
- Inspector MGA.
- Asesor Experto.
- Maestro MGA.

---

# Resultado esperado

El Constructor MGA Pro deberá ser capaz de explicar por qué recomienda una acción, por qué detecta un error y por qué considera que un proyecto es coherente o requiere ajustes.

El usuario no solo recibirá respuestas; recibirá el razonamiento técnico que las sustenta.
